Supervisor lane: Firstmate

The owner talks to one agent. That agent runs the other agents.

Credit. The supervisor is Firstmate, an open-source project by Kun Chen and contributors (MIT licence). Read its own README and docs/architecture.md for the full design. This page does not copy those docs. It says how the owner uses Firstmate and what the owner changed.

What the supervisor does

  • The owner asks for work in plain words: a fix, an audit, an investigation.
  • The supervisor writes a brief for each task and starts a worker agent for it.
  • Each worker gets its own git worktree and its own status file.
  • A small bash watcher sleeps on all status files. It uses no model tokens. It wakes the supervisor only when a worker needs something.
  • The supervisor brings finished work back to the owner: a report, or a pull request to approve.

Why separate sessions, not sub-agents

Upstream Firstmate runs each worker as a normal agent session in a visible terminal window. It does not use a tool's built-in sub-agents. The upstream docs give the reason. A built-in sub-agent is hard to see and hard to steer. Its work can die with its parent session. Upstream records one such loss and added a guard against it (docs/subagent-guard.md).

What the owner changed

The owner runs a private fork, built and running. It has two small changes of the owner's own on top of upstream (both 2026-10-28):

ChangeWhy
Scouts run a plain-English checker (STE100-style, after ASD-STE100 Simplified Technical English) on their report before they say "done".Reports go to a person. The checker flags long sentences and vague words.
A reviewed path moves notes from the agent's own auto-memory into the curated facts file.Facts enter long-term memory only after review.

The first change has a cost. It makes Firstmate depend on the owner's context system. A test that checks "Firstmate never points back at the context system" now fails. The owner accepts this trade-off. See what works today.
