Hooks and rules lane

Rules in a text file are advice. A hook is a script the tool must run. Hooks turn the most important rules into checks.

The owner's Claude Code hooks

These are in the owner's Claude Code settings, checked on 2026-10-30. Each script is short bash. If a script cannot parse its input, it allows the action.

A missing script is not an error: each hook checks that its script exists and exits 0 if not. This is safe, but it can hide a broken hook. One such hook pointed at a missing file until 2026-10-30. It is now removed. A read-only health checker (bin/harness-check) now lists hooks, jobs and plugins so this kind of gap shows up. See What works today.

Upstream supervisor guards

Upstream Firstmate ships its own guards for the supervisor session. The owner did not write these. Read them upstream:

  • docs/cd-guard.md: stops a command that changes directory in an unsafe way.
  • docs/turnend-guard.md: stops the supervisor from ending a turn while work has no live supervision.
  • docs/subagent-guard.md: stops the supervisor from using a tool's built-in sub-agents.

Rules that stay as text

Some rules stay in the map, because a script cannot judge them well. Examples: "Drafts, not sends." "Ask before anything hard to undo." "Say when something is a guess." Agents can still break these. The review surfaces (lane 6) are where the owner catches it.
