Evidence · two worked cases

Testing in public

A claim is worth only the check behind it. Here are two cases where a check proved the setup wrong. Both stay on this page on purpose.

Case 1: a plain-English rule broke a test

The rule

Reports for the owner use Simplified Technical English (STE): short sentences, one idea each, active verbs, no vague words. A small checker, plain-check, tests a file for these rules. It reports "hard" findings (for example, a sentence over 25 words, or a semicolon) and "soft" findings (for example, a passive verb). verified

The change

The owner changed their fork of the supervisor: scouts must run plain-check on their report before they say "done". The change touched the scout-completion skill, the brief builder and one test (commit f33019a6, 2026-10-28). verified

The test that broke

The context system has a one-way rule: the supervisor never points back at the context system. Test T6 checks it. The new scout step calls a tool that lives in the context system. So T6 now fails. verified tests/chain.sh: 36 pass, 1 fail (T6), on 2026-10-31.

The decision

The owner keeps the failing test, and does not delete or weaken it. The test reports a real trade-off: plain reports cost one dependency in the wrong direction. A later fix could move the checker into the supervisor's fork. Then T6 passes again.

This site obeys the same rule. Every page here passed plain-check with 0 hard findings. (The checker reads Markdown, so the scout first turned each page into plain text blocks.)

Case 2: "scouts run without bypass" was wrong

The claim

An earlier version of the operating manual said that scout sessions run with permission checks on.

The check

  1. Read the spawn script's own header. It says: no mode file, or the value bypass, selects the flag that skips permission checks. The value auto selects a model-reviewed mode. verified
  2. Look for the mode file in the supervisor's config folder. It does not exist. verified
  3. List the running Claude worker processes and count their permission flags. All 10 carried the bypass flag, this scout included. verified

The result

The claim was false. It is false by design: bypass is the standing default for every worker (ships, scouts, secondmates, relaunches). Version 0.5 of the manual now says so. It lists the claim in a verification register as "false by design today", with the check to run before anyone may claim otherwise. verified

What happens next

designed One line in the mode file switches later launches to the model-reviewed mode. That mode depends on a settings block that is still under review. The plan: switch it, start one scout, read its task record, then check every spawn for a week.

The pattern

  • Write the claim down.
  • Name the check that would prove it.
  • Run the check, and keep the result even when it is bad.
  • Until a check passes, call the claim "in trial", never a feature.
