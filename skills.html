Lanes 3 and 4 · how instructions load on demand

How skills work

The map is always loaded. A skill is loaded only when a task needs it. This keeps the start of every session small.

Marks: [V] = verified on disk or in this session · [U] = not verified (from tool docs, or a guess). Source: a skills audit on 2026-10-30, re-checked the same day.

What a skill is

A skill is a folder. The folder holds one file, SKILL.md, and can hold scripts or reference files. The file starts with frontmatter:

---
name: stow
description: >-
  File durable facts into the learnings file
  before a session reset or compaction.
---
(the body: steps the agent follows)

The name must match the folder name. The description says when to use the skill. The audit checked 84 skill files. None had missing or bad frontmatter. [V]

How a skill reaches a session

Claude Code lists every skill it can see by name and description at session start. It loads the body only when the agent uses the skill. [V for this session. The mechanism inside the tool: U]

So descriptions are not free. In the supervisor's repo, the list is about 13,000 characters of descriptions before the first prompt. [V]

Why a skill in one repo is invisible in another

A repo's .claude/skills/ folder counts only when the session runs in that repo. The supervisor's repo has 28 skills. A session in any other repo sees none of them. [V]

The user folder would fix this, but nothing links the owner's own skills into it. The setup links the map into five tools and links no skills. [V]

User-invoked and agent-only skills

  • User-invoked. The person types /name. Six of the supervisor's 28 skills are like this, for example /stow and /bearings. [V]
  • Agent-only. The frontmatter says user-invocable: false. The skill is not in the / menu. The model still sees its description and loads it when a trigger matches. [U]

The trigger index

Upstream Firstmate keeps one skill that is only a table: 21 agent-only skills and the exact event that must load each one. For example: "before you treat a report as complete, load the completion-gate skill". The agent reads one table instead of guessing from 21 descriptions. [V]

Workflows with no skill

Some repeated jobs have no skill and no trigger. People or agents do them by hand: [V]

  • Read the work index. A hook builds it. No rule in either map tells agents to read it.
  • Save facts before compaction. The stow skill says "before compaction", but nothing starts it.
  • End-of-session note. A prompt hook text. It works only in Claude Code, and only on the exact words "end of session".
  • Find an existing script. The owner's tool folder has no index. The upstream script list misses 42 scripts. So agents write new ones.
