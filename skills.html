Skills

How skills work

The map is always loaded. A skill loads only when a task needs it. This keeps the start of each session small.

Prefer a picture? The Skill map shows the lanes, the skills and the guards. Click any box.

Source: a skills audit on 2026-10-30. Each fact was checked on disk or in a session, unless it says "not checked".

What a skill is

A skill is a folder. It holds one file, SKILL.md, and can hold scripts. The file starts with a short header:

---
name: stow
description: >-
  File durable facts into the learnings file
  before a session reset or compaction.
---
(the body: steps the agent follows)

The name matches the folder. The description says when to use the skill. The audit checked 84 skill files. None had a bad header.

How a skill reaches a session

At session start, Claude Code lists every skill it can see, by name and description. It loads the body only when the agent uses the skill. This was seen in a session. How the tool does it inside was not checked.

So descriptions are not free. In the supervisor's repo, the list is about 13,000 characters before the first prompt.

A skill in one repo is invisible in another

A repo's .claude/skills/ folder counts only when the session runs in that repo. The supervisor's repo has 28 skills. A session in any other repo sees none of them.

The user folder would fix this. But the setup links the map into five tools, and links no skills.

Two ways a skill starts

  • The person types it. For example /stow or /bearings. Six of the supervisor's 28 skills work like this.
  • The agent loads it. The header says user-invocable: false, so the skill is not in the / menu. The model still sees its description and loads it when a trigger matches (not checked).

The trigger index

Upstream Firstmate keeps one skill that is only a table. It lists 21 agent-loaded skills and the exact event that must load each one. For example: "before you treat a report as complete, load the completion-gate skill". The agent reads one table instead of guessing from 21 descriptions.

Jobs with no skill

Some repeated jobs have no skill and no trigger. People or agents do them by hand:

  • Read the work index. A hook builds it. No rule tells agents to read it.
  • Save facts before compaction. The stow skill says "before compaction", but nothing starts it.
  • End-of-session note. It works only in Claude Code, and only on the exact words "end of session".
  • Find an existing script. The owner's tool folder has no index. The upstream script list misses 42 scripts. So agents write new ones.
