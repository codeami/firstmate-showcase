Above the crews · the task layer

Task management

The crews do one task each. Above them, the owner needs a place to decide which tasks exist. That is the task layer.

Marks: in trial = in use by the owner, not yet proven · designed = written down, not run.

The sprint board in trial

The owner tracks projects on a single-page sprint board. Every project moves through six phases. A task leaves a phase only when the phase's exit check is true.

PhaseWho leadsAttentionExit check
RequirementsOwner30%The problem, the user and the success measure are on one page.
AnalysisOwner25%The options are compared. One is chosen, and the reason is written down.
DesignOwner and AI10%An agent can build from the spec without questions.
BuildThe agent crews5%The agent output runs end to end on real data.
ValidationOwner25%Evidence shows that it meets the success measure.
ReleaseOwner and AI5%It is live or sent, and the result is logged.

Note the attention column. The owner spends most attention at both ends: deciding what to build, and checking that it works. The build itself gets the least, because the crews do it.

The board's rules

  1. Capture first. Sort later. Every new item goes to the inbox.
  2. Pin three tasks each morning. Do those first.
  3. Each project has one next action. If you cannot name it, the project is not active.
  4. A task leaves a phase only when the phase's exit check is true.
  5. The crews build. Do not write by hand what an agent can make and you can check.
  6. Validation is evidence, not opinion: a test run, a metric, a review or a user's answer.
  7. Names state the intent. Verb first, one idea per task.
  8. Review each day: empty the inbox, look at overdue tasks, pin tomorrow's three.

The operations board designed

The operating manual (see Cast and authority) defines one board as the only queue. Its columns:

Intake → Chartered → In Progress → Review → Shipped / Published
                                          (plus Parked, with a date)
  • A card enters In Progress only with an owner and an autonomy level.
  • A card leaves Review only on the owner's word.
  • Every card carries its role, its level, a link to its artifact, and the one action that reverses it.

An intake table sorts each new card: staff task, ship, scout, runner, secondmate, or park. The first test that matches wins. A card that is half staff work and half code is split in two.

The staff-bot engine designed, not run

The manual plans a second engine for staff work: persistent bots with their own computers and routines. A Chief of Staff bot would keep the board, sweep the inbox each morning and write a daily brief. An Editor bot would draft posts outside any repo. An Analyst bot would gather evidence.

None of this has run. The manual's own register says: one month of board operation before any claim. Until then, the owner or the Chief of Staff seat moves cards between the engines by hand.
