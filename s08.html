Planning side: a planner agent and stage contracts

Two agents split the thinking. A planner on a cheaper model does research, audits and plans. Claude Code builds.

The software factory room

One task is one run through eight numbered stages, in order. Each stage writes one file. The next stage starts only when the earlier file exists. Where a stage has a gate, its file must carry approved: <date>.

StageJobOwner gate
01 intentThe owner's words, as numbered items I1…Inyes
02 specAcceptance criteria A1…An, each linked to an intent itemsometimes
03 tasksSplit the work, pick scout or ship, write the briefno
04 buildWorktree, branch, testsno
05 validatePre-push gate: review, test, docs, lintsometimes
06 reviewAsked versus deliveredyes
07 landMerge on the owner's wordyes
08 learnSession notes and proposed rule editsyes

Rule: fix a wrong result in the stage file, not in the output. The stage file is the program.

The chain check

bin/chain-check <run folder> reads a run's intent and spec files. It checks ids, approval and coverage. Every acceptance criterion must point to an intent item. A spec must not exist before the owner approves its intent.
