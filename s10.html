Influences and comparisons

This setup borrows from three public bodies of work. It solves a narrower problem than each: one person, several agent tools, one set of rules.

The two main sources

ICM (Jake Van Clief)

Interpretable Context Methodology. A short map, routing tables, numbered stages with a contract each, and taste rules in their own files. It decides what an agent reads, and when.

Repo · paper: arXiv 2603.16021

Kun Chen's agent stack

One dispatcher (Firstmate), disposable worktrees, a gate before push (no-mistakes), rule proposals from logs (backpass), review pages (lavish-axi). It decides how agents are run, checked and corrected.

Reading (a judgement, not a measurement): this setup follows ICM closely on the context side. On the Kun Chen side, it runs the supervisor and the review tool. It does not yet run the parts that close the loop. Those are the nightly rule proposals and the pre-push gate on every project.

A third source: Matt Pocock's skills

mattpocock/skills is strongest on intent capture (structured interviews), specs and review. This setup has none of those skills installed. Ideas worth borrowing: a short interview before a spec, and a shared glossary.

What is not claimed

  • No head-to-head test of these approaches exists here.
  • Token numbers in all three sources are their own claims. None was reproduced here.
